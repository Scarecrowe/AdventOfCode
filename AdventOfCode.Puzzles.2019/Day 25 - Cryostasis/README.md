# 🎄 Advent of Code 2019 - Day 25: Cryostasis

## 📜 Puzzle Overview

This puzzle uses the Intcode computer as a text adventure engine.

The program outputs ASCII text describing rooms, doors, and items, and it accepts ASCII commands such as movement and item interactions.

The overall goal is to explore the ship, collect the correct combination of safe items, and pass the security checkpoint to obtain the access code.

In this implementation, Part 1 is solved with a fixed command sequence rather than a general search.

Part 2 does not compute a second puzzle answer and instead returns a completion message.

---

## 🧩 Part 1

Navigate the ship, collect a specific set of items, pass the checkpoint, and extract the final code.

### 💡 Approach

- Create an `IntcodeCpu` from the puzzle input program
- Send a hardcoded sequence of ASCII commands to the CPU
- Move through the ship using direction commands
- Pick up selected safe items:
  - `mutex`
  - `loom`
  - `sand`
  - `wreath`
- Clear previous output just before the checkpoint attempt
- Move east into the checkpoint test
- Convert the resulting ASCII output into text
- Extract the numeric code from that output

---

## 🧩 Part 2

Return the completion message instead of solving another computational step.

### 💡 Approach

- Do not run additional puzzle logic
- Return the fixed completion text from the day entry class

## 🧠 Code Breakdown

### `Day25.cs`

This is the puzzle entry point.

- Loads the puzzle input
- Calls the silver and gold solutions

For Part 1:

- Creates `new Cryostasis(this.Input[0])`
- Calls `Run()`

For Part 2:

- Returns:

    You have enough stars to [Align the Warp Drive]

One implementation detail worth noting is that the constructor sets:

    this.DayTitle = "Category Six";

even though this folder and puzzle are for Day 25, `Cryostasis`.

---

### `Crostasis.cs`

This file contains the main puzzle logic.

The class itself is named:

- `Cryostasis`

It stores:

- `Cpu`

The constructor does this:

    this.Cpu = new(program);

So the puzzle input is expected to be one comma-separated Intcode program string.

---

### Intcode ASCII Interaction

The solver relies on ASCII-based Intcode helpers.

The main Part 1 method repeatedly uses:

    this.Cpu.RunAsciiCommand(...)

This means commands are sent to the Intcode computer as text instructions such as:

- `north`
- `south`
- `east`
- `west`
- `take mutex`

So the Intcode program is being treated as an interactive text adventure.

---

### `Run()`

`Run()` performs the scripted solution for Part 1.

It begins with:

    this.Cpu.RunAsciiCommand();

This appears to start the program and process the initial room output.

It then sends a fixed navigation and item-collection route through the ship.

The command sequence is:

    north
    north
    north
    take mutex
    south
    south
    east
    north
    take loom
    south
    west
    south
    west
    west
    take sand
    south
    east
    north
    take wreath
    south
    west
    north
    north
    east

So the solver is not exploring dynamically.
It already knows the correct path and the safe items to collect.

---

### Checkpoint Attempt

Just before the final move into the checkpoint, the solver clears prior output with:

    this.Cpu.Output.Clear();

It then runs:

    this.Cpu.RunAsciiCommand("east");

This final movement command triggers the checkpoint resolution using the currently held items.

That means only the output generated by the checkpoint attempt remains in the CPU output queue for parsing.

---

### Extracting the Answer

After the final checkpoint output is produced, the method converts the ASCII output into text:

    this.Cpu.Output.Select(c => (char)c).ToArray().Join()

It then extracts the numeric portion using:

    .Numbers()

So the silver answer is the number embedded in the final text returned by the Intcode adventure after successfully crossing the checkpoint.

---

### `Play()`

The class also contains an interactive helper method:

    Play()

This method allows the puzzle to be played manually through the console.

Its flow is:

- run the CPU
- print all ASCII output
- read a line from the console
- convert that input into ASCII
- enqueue it into the CPU
- continue until the CPU terminates

At a high level it behaves like:

    run cpu
    while cpu is not terminated
        print output
        clear output
        read console input
        enqueue ascii command
        run cpu

This appears to be a manual exploration tool used to discover the map, commands, and correct item combination.

---

### Manual Command Encoding

The interactive mode uses:

    IntcodeCpu.StringToAscii(...)

to turn typed commands into ASCII values before they are queued into the CPU input stream.

So both the scripted solver and the interactive mode rely on the same text-based Intcode interface.
