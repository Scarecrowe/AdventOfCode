# 🎄 Advent of Code 2015 - Day 11: Corporate Policy

## 📜 Puzzle Overview

Santa needs a new password.

Passwords must be exactly eight lowercase letters and are generated by incrementing the current password until a valid one is found. A valid password must:

- include at least one increasing straight of three letters, such as `abc`, `bcd`, or `xyz`
- not contain the letters `i`, `o`, or `l`
- contain at least two different, non-overlapping pairs of letters, such as `aa`, `bb`, or `zz` :contentReference[oaicite:0]{index=0}

Part 1 asks for the next valid password after the given input.

Part 2 asks for the next valid password after the Part 1 result. :contentReference[oaicite:1]{index=1}

---

## 🧩 Part 1

Find the next valid password after the given input.

### 💡 Approach

- Treat the password like an incrementing base-26 value
- Increment from the end of the string
- Skip disallowed letters as soon as they appear
- Check whether the candidate contains:
  - a straight of three increasing letters
  - no disallowed letters
  - two non-overlapping pairs
- Stop at the first valid result

---

## 🧩 Part 2

Find the next valid password after the Part 1 answer.

### 💡 Approach

- Reuse the same password generator
- Feed the Part 1 result straight back into it
- Return the next valid password found after that

### `CooperatePolicy.cs`

This class contains the password generation logic.

It stores the password as an array of ASCII character codes and repeatedly increments that array until a valid password is found.

The disallowed letters are stored as ASCII values:

- `105` for `i`
- `108` for `l`
- `111` for `o`

The main entry point is:

- `Generate(string password)`

This method:

- converts the input password into an integer array
- increments the password
- rejects candidates containing disallowed letters
- returns the first candidate that passes the remaining rule checks :contentReference[oaicite:3]{index=3}

---

### Incrementing the Password

The `Increment()` method handles password stepping.

It works from right to left:

- increment the current position
- skip over disallowed characters immediately
- if the character goes past `z`, wrap it to `a`
- carry the increment to the character on the left

At a high level, it behaves like this:

    xx -> xy
    xz -> ya
    azzzzzzz -> baaaaaaa

This makes the password behave like a rolling sequence rather than a plain string replacement. :contentReference[oaicite:4]{index=4}

---

### Disallowed Character Check

The `HasDisallowedAscii()` method scans the current password and rejects it if any character matches the disallowed ASCII list.

This check exists separately from the increment logic, even though disallowed letters are also skipped during incrementing. That means invalid candidates are filtered safely even if one somehow appears in the array during processing. :contentReference[oaicite:5]{index=5}

---

### Straight Check

The `HasStraight()` method looks for three consecutive increasing letters.

It tracks:

- the previous character
- the current straight length

If the next character is exactly one greater than the previous one, the count increases. As soon as the count reaches `3`, the password passes this rule.

Examples of valid straights include:

- `abc`
- `bcd`
- `xyz` :contentReference[oaicite:6]{index=6}

---

### Double Pair Check

The `HasDouble()` method checks for two non-overlapping pairs.

It tracks:

- the previous character
- the index of the last accepted pair
- how many valid pairs have been found

A pair is counted only if:

- the current character matches the previous one
- it does not overlap the previous accepted pair

Once two valid pairs are found, the password passes this rule.

This matches the puzzle requirement that pairs must be separate and not overlap. :contentReference[oaicite:7]{index=7}

## 🛠 Implementation Notes

- Password characters are processed as ASCII integers rather than raw characters
- Part 1 and Part 2 both use the same generator method
- Incrementing and validation are separated into focused helper methods
- Disallowed letters are skipped during incrementing and also checked explicitly afterwards
- The generator returns as soon as a valid password is found, so no unnecessary work is done beyond the first match :contentReference[oaicite:8]{index=8}
